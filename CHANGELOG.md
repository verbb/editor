# Changelog

## Unreleased

### Added
- Added a full frame to `<verbb-editor>`, with header, above, actions and footer slots, a Post button, a character limit, a local draft, post errors and ⌘↵ or Enter to post, which adapts to its own width. The bare text box is now the editor input, `<verbb-editor-input>`.
- Added collapsing for a `collapsible` editor only when focus moves elsewhere on the page or someone presses outside it, never for a press on text inside it, a switch to another window or a password manager's menu, and never while a field in its slots holds something someone entered.
- Added a `reply-to` attribute to `<verbb-editor>`, which shows who a reply is to with a button to cancel it and fires a cancelable `editor-reply-cancel` event.
- Added an icon toolbar under the text with tooltips and shortcuts, a More menu with undo, redo and formatting help, a `toolbar` option for choosing what sits on it or leaving it out, a `toolbarPosition` option for putting it above the text instead, and a formatting bubble over selected text. With content in the above or footer slots, the text and toolbar sit in a box of their own that takes the focus ring, rather than the whole frame.
- Added one Link control that takes an address or searches the site's pages, suggests pages before a search, and shows a card for the link under the caret.
- Added an uploads tray with progress, retry, alt text and removal, which the whole editor accepts files into by dropping or pasting.
- Added GIF search through GIPHY. A context's `GifConfig`, or the `gifs` option, puts a GIF control on the toolbar that searches GIPHY in a popover, loaded when first opened, and the chosen GIF goes with the document rather than inside it, read with `getGif()` or submitted under the element's `gif-name`. `Giphy::normalize()` checks a GIF before it's saved, and `@verbb/editor/gifs` offers the same search to pages without the editor.
- Added an optional description and image to mention and page results, `describe` callables on `MentionConfig` and `ElementLinkConfig`, and suggestions for an empty search.
- Added a `craft` theme that takes the Control Panel's colours, sent by `browserOptions()` on Control Panel requests, and a `data-options` attribute.
- Added a prebuilt browser bundle to the Composer package, registered through `EditorAsset` or the `editorAssets()` Twig function, so plugins no longer build their own copy of Tiptap.
- Added on-demand loading to the prebuilt bundle, which fetches links, mentions and uploads only for editors that use them, with `Editor.create()`, `loadFeatures()`, an element `ready` promise and `editor-ready` and `editor-error` events.
- Added `EditorConfig::browserOptions()`, which gives the browser its features, action URLs, CSRF token, placeholder and translated labels in one call.
- Added a `request` option to `new Editor()`, `<verbb-editor>` and `<verbb-editor-input>`, with extra headers, such as a bearer token read fresh before each request, and the credentials mode for mention, page search and upload requests.
- Added an `$endpoints` argument to `browserOptions()`, which sends an enabled feature's requests to a plugin's own controller, and `EditorConfigs::resolveRequestConfig()`, which gives that controller the same context, scope and authorisation checks as Editor's endpoints.
- Added an `authorize` hook and `resolveScope` callable to contexts, so plugins control who can use each resource endpoint and for what.
- Added `Documents::renderAll()` for rendering lists with one lookup per kind of reference, and `Documents::resolve()` for preparing saved documents for editing.
- Added document size limits and per-document image and attachment limits to contexts.
- Added `getTextLength()` to the editor and `RichText::getTextLength()`, which count text the way the character limit does, so a plugin's own limit on the server can match it.
- Added trusted user query criteria and an eligibility callable to mentions, and per-type query criteria to Craft links.
- Added upload safety for every upload, whatever a context allows. SVG, HTML, XML, script and program files are refused by name and by contents, as is any file whose contents don't match its extension, and these types are never offered to the browser.
- Added removal of image metadata, including where a photo was taken, without re-encoding, after turning a phone photo upright. TIFF images are refused, and HEIC and AVIF images are accepted only when PHP has the Imagick extension to strip them, which `UploadSafety::canStripHeicAndAvif()` reports.
- Added a refusal for every upload while Craft's temporary upload filesystem has public URLs, since files wait there unchecked until a document keeps them. `UploadSafety::temporaryUploadsArePublic()` lets a settings page warn about it.
- Added `UploadSafety::check()`, which applies the same rules to uploads that don't go through Editor, and `UploadRefusedException`, whose `reason` says why a file was refused.
- Added automatic cleanup of abandoned uploads through Craft's garbage collection.
- Added `RichText::fromJson()` and `RichText::fromText()`.
- Added translatable browser strings through a `labels` option, and `ariaLabel` and `ariaLabelledBy` options.
- Added `isUploading()`, an `onUploadState` option and an `editor-upload-state` event, and a form won't validate while an upload is in flight or after one failed.
- Added custom server extensions to contexts through `EditorConfig::$extensions`.
- Added keyboard mention suggestions showing people with their avatar and role, with a plain-words message and Try again when they can't be loaded.
- Added right-to-left layouts to the editor, with the toolbar's arrow keys, popovers, shortcuts and directional icons following the text, and Windows High Contrast styles for focus, popovers, pressed tools and suggestions.
- Added screen reader announcements for posting, finished uploads and reaching or passing the character limit, which also marks the text invalid while it's over, with new `uploaded` and `either` labels.
- Added larger touch areas for Cancel reply and the uploads tray's Remove and ALT controls, and a fade at the edge of the toolbar when it scrolls in a narrow editor.
- Added form participation, required validation, reset, disabled/read-only support, `focus()`, label association and `aria-required` and `aria-invalid` handling to `<verbb-editor>` and `<verbb-editor-input>`.
- Added explicit browser HTML import and adoption documentation for lifecycle, forms and resource ownership.
- Added user guides for building a plugin with Editor and for using Editor from a site module.
- Added the `@verbb/editor` browser package with a vanilla mount API, Tiptap integration, light, dark and none themes built on `--verbb-editor-*` tokens, multi-instance support and mentions. The dark theme sits on the host's own surface.
- Added the PHP document layer ported from `verbb/tiptap`: `RichText`, structured node extensions, sanitising, HTML and plain-text rendering and the `Documents` service.
- Added the `EditorConfigs` registry with capability config models (`AssetConfig`, `ElementLinkConfig`, `MentionConfig`).
- Added endpoints for element search, mention search and asset uploads.
- Added `Documents::extractReferences()` and `extractMentions()`.
- Added `editorHtml` and `editorPlain` Twig filters.

### Changed
- Images and attachments now sit in the uploads tray while editing and are saved after the text, rather than being placed at the caret.
- Editor now requires Craft CMS 5.10 or greater.
- Rendering no longer depends on the viewer's Control Panel permissions, so guests and members see the mentions, links and images authors inserted. A context can opt in to `requireViewPermission`.
- Documents now store references only. URLs and file details always come from resolution, and `Documents::resolve()` provides them for editing.
- A document may now only show the Asset IDs its plugin passes as associated with it.
- Mentions and Craft links nobody can vouch for now degrade to their text, and images and attachments are removed, in both HTML and plain text.
- Rendering without a context now turns structured nodes into text. `editorHtml` now takes a context as its second argument.
- Strings are now documents only when they decode to a `doc` object or a non-empty array of objects with a string `type`. Any other string is literal text, and HTML is never guessed. Browser and server share this rule.
- An empty document now serialises as `{"type":"doc","content":[]}`, and `<verbb-editor>` submits an empty string.
- Empty now means no visible text and no mention, image or attachment, in both the browser and on the server.
- Content for a disabled feature now degrades with blocks kept separate, in both the browser and on the server. A disallowed heading level becomes the nearest allowed one.
- Plain text now separates list items and nested blocks, and matches between browser and server.
- Uploads now default to common image types, attachments need an explicit extension list, file size defaults to Craft's limit, and each user can have up to 20 pending uploads.
- Finalised uploads now keep their original filename, and uploading through one context and rendering through another now works.
- `Assets::finalize()` now takes the Asset IDs a plugin has already associated, so edits keep existing media.
- Mention search now matches name fields only, never email addresses, and only active users.
- Endpoints now respond in Craft's usual format, with server refusal messages passed through to authors.
- Consumers now pass `EditorConfig::browserOptions()` rather than a `baseUrl`.
- Renamed and moved classes to Craft's standard layout. `EditorConfigs::register()`, `get()`, `require()`, `has()` and `getAll()` are now `registerConfig()`, `getConfigByHandle()`, `requireConfigByHandle()` and `getAllConfigs()`.
- Updated the required version of `verbb/base` to 3.0.19.
- Uploads now send cookies to another origin only when `request.credentials` is `include`, as mention and page searches do.
- `@verbb/editor` now carries the same version as `verbb/editor`, and its package includes a README and licence.

### Fixed
- Fixed a document repeating a mark on the same text making rendering fail, and a link inside another link being rendered as markup browsers rearrange.
- Fixed submitted links being able to drop `noopener`, `noreferrer` and `nofollow` from their `rel`.
- Fixed the server keeping links the browser refused, where a numeric character reference without its semicolon hid the scheme or the address was only Unicode spaces.
- Fixed `RichText::fromHtml()` failing on HTML that holds only head content, such as a comment, `<script>` or `<meta>`.
- Fixed `Assets::finalize()` moving a document's earlier uploads before refusing a later one, which left them moved with no document saved. Every reference is now checked before any file moves.
- Fixed the character limit counting text differently from the server's plain text, so a post with several paragraphs or emoji could be held in the browser or refused on the server unexpectedly.
- Fixed the character limit and upload limit messages reading “1 characters” or “1 photos”. They now use ICU plural forms, which translations can follow for any language.
- Fixed importing `@verbb/editor` during a server render failing without a DOM, and its types resolving as `any` under Node's own module resolution.
- Fixed the editor's Post button, tooltips and alt-text badge losing their font size and weight when it inherits the page's font.
- Fixed undo reaching back past the loaded document and emptying the editor.
- Fixed changing most `<verbb-editor>` attributes rebuilding the editor and losing focus and uploads.
- Fixed pressing Enter in the link or alt text popover submitting the host form.
- Fixed strings that parse as JSON but aren't documents erasing content.
- Fixed `example.com` and email addresses in the link panel becoming broken relative links.
- Fixed the same URL being treated differently by the browser and the server.
- Fixed attributes such as `id` and `url` being rendered onto public output.
- Fixed mention menu scrolling, positioning and dismissal, and Enter abandoning a mention during a search.
- Fixed pasting from Office apps losing the text, and dropping an unsupported file navigating away.
- Fixed lists and headings losing their appearance under a site's CSS reset.
- Fixed emptying a document that allows attachments leaving a blank attachment behind.
- Fixed rendering failing when Craft links were enabled but element links weren't.
- Fixed Craft link scoping being ignored, and search returning short lists when results were ineligible.
- Fixed custom server extensions being removed whenever a context was used.
- Fixed `RichText::fromHtml()` giving mentions and attachments a text child.
- Fixed an ordered list's start number being lost.
- Fixed browser declarations and theme exports so built-package consumers resolve the supported API.
